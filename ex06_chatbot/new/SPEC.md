# 목표



> 출발 문장: 중고차 리스트를 소비자가 보고, 원하는 중고차를 클릭했을 때 가격 · 스펙 등의 세부사항을 확인할 수 있도록 하고 싶다.
> 이번 범위: 풀스택 바이브코딩 (1) — 화면만 만들고, 데이터는 더미(메모리)로 씀

## 인터뷰 질문과 답

| 질문 | 정한 답 | 정한 이유 |
|---|---|---|
| 누가 쓰나? | seller(판매자: 개인 · 딜러) · buyer(구매자: 소비자) | 판매자는 매물을 올리고, 구매자는 목록과 상세를 보고 고름 |
| 매물 카드에는 어떤 정보를 보여주나? | 차명 · 대표 사진 · 가격 · 연식 · 주행거리 | 목록에서 한눈에 후보를 추리기 위함 |
| 상세 화면에는 무엇을 더 보여주나? | 기본 스펙(배기량 · 변속기 · 연비 · 색상 · 차종) · 사고/정비 이력 · 옵션 목록 · 판매자 연락처 | 다른 매물과 비교해 가성비를 따지기 위함 |
| 판매 상태는 몇 가지인가? | 판매중 · 판매완료 | 처음엔 단순하게 시작 |
| 목록 정렬은 어떻게 하나? | 정렬 버튼 제공(최신 등록순 · 낮은 가격순 · 짧은 주행거리순 · 최신 연식순), 처음엔 최신 등록순 | 구매자마다 중요하게 보는 기준이 다름 |
| 사진은 어떻게 다루나? | 등록 폼에서 사진 업로드 포함 | 중고차는 사진 없이 판단하기 어려움 |
| 로그인이 필요한가? | 미정 | 풀스택 바이브코딩 (2)에서 결정 — 이번엔 누구나 등록 · 판매완료 처리 가능 |

## 사용자 스토리

- US-01: 구매자(buyer)로서, 매물 목록을 최신 등록순 · 낮은 가격순 · 짧은 주행거리순 · 최신 연식순으로 바꿔 보고 싶다. 왜냐하면 내가 중요하게 보는 조건에 맞는 차를 빨리 찾아야 하니까.
- US-02: 구매자(buyer)로서, 매물 카드를 클릭해 기본 스펙 · 사고/정비 이력 · 옵션 · 판매자 연락처를 확인하고 싶다. 왜냐하면 다른 매물과 비교해 가성비를 따져야 하니까.
- US-03: 구매자(buyer)로서, 판매 상태별로 매물을 걸러 보고 싶다. 왜냐하면 이미 팔린 차를 빼고 지금 살 수 있는 차만 보고 싶으니까.
- US-04: 판매자(seller)로서, 차명 · 가격 · 연식 · 주행거리와 사진으로 내 차를 매물로 등록하고 싶다. 왜냐하면 구매자에게 내 차를 보여줘야 팔 수 있으니까.
- US-05: 판매자(seller)로서, 팔린 매물을 '판매완료'로 바꾸고 싶다. 왜냐하면 이미 팔린 차에 구매자 문의가 오지 않게 해야 하니까.

## 인수 기준 (Given / When / Then)

### AC-01 목록 정렬 (US-01)
- Given: 매물 목록 화면에서
- When: 화면을 처음 열고, 이어서 '낮은 가격순' 정렬 버튼을 누르면
- Then: 처음에는 매물 카드가 최신 등록순으로 차명 · 사진 · 가격 · 연식 · 주행거리와 함께 표시되고, 버튼을 누른 뒤에는 가격이 낮은 카드부터 다시 표시됨

### AC-02 매물 상세 (US-02)
- Given: 매물 목록 화면에서
- When: 매물 카드 하나를 클릭하면
- Then: 상세 화면으로 이동해 그 차의 가격 · 기본 스펙 · 사고/정비 이력 · 옵션 목록 · 판매자 연락처가 표시되고, '목록으로' 버튼을 누르면 목록 화면으로 돌아감

### AC-03 판매 상태 필터 (US-03)
- Given: 매물 목록 화면에 판매중 · 판매완료 매물이 섞여 있을 때
- When: 상단의 '판매중' 탭을 누르면
- Then: 판매중인 매물 카드만 남고, '전체' 탭을 누르면 모든 매물 카드가 다시 표시됨

### AC-04 매물 등록 (US-04)
- Given: 매물 등록 폼에서
- When: 차명 · 가격 · 연식 · 주행거리를 입력하고 사진을 골라 '등록'을 누르면
- Then: 고른 사진이 미리보기로 보이고, 등록 후 목록 맨 위에 그 사진과 입력한 값이 담긴 새 매물 카드가 '판매중'으로 표시됨

### AC-05 등록 입력 확인 (US-04)
- Given: 매물 등록 폼에서
- When: 가격 칸을 비우거나 숫자가 아닌 값을 넣고 '등록'을 누르면
- Then: 목록에 추가되지 않고 가격 칸 아래에 '가격을 숫자로 입력하세요' 안내가 표시됨 (다른 필수 칸도 칸마다 안내가 표시됨)

### AC-06 판매완료 처리 (US-05)
- Given: 상세 화면에서 상태가 판매중인 매물을 보고 있을 때
- When: '판매완료로 변경' 버튼을 누르면
- Then: 그 매물만 '판매완료' 배지가 붙고, 목록에서 그 카드가 흐리게 표시됨

## 범위 밖 (이번엔 안 함 · Won't)

| 만들지 않을 것 | 이유 |
|---|---|
| 로그인 · 회원가입 | 인터뷰에서 '미정'으로 둠 — 풀스택 바이브코딩 (2)에서 결정 |
| 채팅 · 쪽지 | 상세 화면의 판매자 연락처 표시만으로 문의 목적을 충족함 |
| 찜(관심 매물) | 로그인이 미정이라 누구의 찜인지 저장할 근거가 없음 |
| 나란히 비교 화면 | 이번엔 정렬 · 상세 화면으로 비교함 |
| 키워드 검색 | 정렬 · 판매 상태 필터로 충분함 |
| 온라인 결제 · 계약 | 이번 범위는 화면 + 더미 데이터뿐이라 실제 돈이 오가는 흐름은 만들 수 없음 |
| 시세 추천 · AI 추천 | 근거 데이터가 없고 범위만 키움(#34) |
